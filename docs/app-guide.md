# 메뉴 원가·마진 계산기 앱 설명서

카페·음식점 같은 소규모 매장을 위한 원가 계산 앱입니다. 식자재 단가와 메뉴 레시피를 입력하면 메뉴별 원가, 원가율, 판매 채널별 순이익, 목표 원가율에 맞는 적정 판매가를 계산합니다. 재료 가격을 바꾸면 그 재료를 쓰는 모든 메뉴의 숫자가 바로 다시 계산됩니다.

- 플랫폼: Flutter (Android, iOS)
- 상태 관리: Riverpod
- 백엔드: Firebase 익명 로그인 + Cloud Firestore
- 저장소: https://github.com/hhy0902/menu-cost-calc

---

## 1. 화면 구성

하단 탭 3개(메뉴, 식자재, 설정)에서 시작하고, 메뉴와 식자재는 각각 상세·편집 화면으로 이어집니다.

| 화면 | 하는 일 |
|---|---|
| 메뉴 (대시보드) | 모든 메뉴를 원가율이 높은 순으로 보여줍니다. 경고 원가율 이상이면 빨간색, 문제가 있는 메뉴는 "재료 확인 필요"로 표시합니다. |
| 메뉴 상세 | 판매가·원가·원가율, 재료별 원가 비중, 채널별 순이익, 적정 판매가를 보여줍니다. 복제·수정 버튼이 있습니다. |
| 메뉴 추가·수정 | 이름, 판매가, 채널별 판매가, 레시피(재료·사용량·적용 채널)를 입력합니다. 입력하는 동안 예상 원가와 원가율이 바로 보입니다. |
| 식자재 목록 | 재료별 구매량·구매가(또는 "직접 만듦")와 단위당 단가를 보여줍니다. |
| 식자재 추가·수정 | 이름, 단위(g·ml·개), 구매량, 구매가, 수율을 입력합니다. 직접 만드는 재료(반제품)는 레시피와 완성량을 입력합니다. |
| 설정 | 경고 원가율, 목표 원가율, 부가세 포함 여부, 판매 채널과 수수료율을 정합니다. |

## 2. 기능

### 2.1 식자재
- 이름, 단위, 구매량, 구매가를 넣으면 **단위당 단가**를 자동 계산합니다.
- **수율**: 양파처럼 손질하면 양이 줄어드는 재료는 손질 후 남는 비율(예: 90%)을 넣습니다. 레시피 사용량은 손질 후 양으로 입력합니다.
- 메뉴나 반제품에서 쓰고 있는 재료를 지우려 하면, 사용 중인 메뉴·반제품 이름을 먼저 보여줍니다.
- 다른 곳에서 쓰는 재료의 단위를 바꾸면, 사용량도 새 단위로 고쳐야 한다고 경고합니다.

### 2.2 반제품 (직접 만드는 재료)
- 시럽·소스·베이스처럼 매장에서 직접 만드는 재료입니다. 식자재 편집에서 **"직접 만드는 재료"**를 켜면 구매가 대신 **레시피**와 **완성량**을 입력합니다.
- 단가는 레시피 재료비 합 ÷ 완성량입니다. 재료값이 바뀌면 반제품 단가와 그 반제품을 쓰는 메뉴 원가가 함께 바뀝니다.
- 반제품 레시피에는 **사 온 재료만** 넣을 수 있습니다. 반제품 안에 반제품을 넣지 못하도록 막아 두었습니다.

### 2.3 메뉴
- 기본 판매가와 레시피(재료별 사용량)를 입력합니다.
- **채널별 판매가**: 배달앱 가격이 다르면 채널마다 따로 넣습니다. 비워 두면 기본 판매가를 씁니다.
- **부자재 채널 지정**: 레시피 줄마다 적용 채널을 고를 수 있습니다. 컵·뚜껑·포장용기처럼 배달에만 드는 부자재는 배달 채널만 선택합니다. 아무것도 고르지 않으면 모든 채널에 적용됩니다.
- **복제**: 메뉴 상세의 복제 버튼으로 레시피·채널 가격·부자재 설정을 그대로 복사한 새 메뉴를 만듭니다. 아이스/핫, 사이즈별 메뉴를 만들 때 씁니다.

### 2.4 설정
- **경고 원가율**: 이 값 이상인 메뉴는 빨간색으로 표시합니다. 기본 35%.
- **목표 원가율**: 적정 판매가 계산 기준입니다. 기본 30%.
- **판매가에 부가세 10% 포함**: 일반과세자는 켭니다. 켜면 판매가 ÷ 1.1(공급가액)을 실제 매출로 보고 계산합니다. 기본 켜짐.
- **판매 채널**: 채널 이름과 수수료율을 정합니다. 기본값은 매장 0%, 배달앱 10%이며 실제 계약 조건으로 바꿔 씁니다. 채널 이름을 바꿔도 메뉴와의 연결은 유지됩니다.

### 2.5 경고 표시
| 상황 | 표시 위치 |
|---|---|
| 레시피의 재료가 삭제됨 | 대시보드 "재료 확인 필요", 상세 경고 카드, 해당 줄 "삭제된 재료" |
| 반제품 속 재료가 삭제됨 | 대시보드 "재료 확인 필요", 상세 해당 줄 "반제품 재료 확인", 식자재 목록 |
| 부자재 줄의 채널이 모두 삭제됨 | 대시보드 "재료 확인 필요", 상세 경고 카드, 메뉴 편집 해당 줄 |

## 3. 계산 방법

모든 계산은 `lib/domain/cost_calculator.dart` 한 곳에 있습니다. 단가·원가 같은 계산 값은 저장하지 않고 화면을 그릴 때마다 계산하므로, 재료값이 바뀌어도 숫자가 어긋나지 않습니다.

| 값 | 식 |
|---|---|
| 일반 재료 단위당 단가 | 구매가 ÷ 구매량 ÷ 수율 |
| 반제품 단위당 단가 | Σ(레시피 재료 단가 × 사용량) ÷ 완성량 |
| 공통 원가 | 모든 채널에 적용되는 레시피 줄의 (단가 × 사용량) 합 |
| 공급가액 | 부가세 포함이면 판매가 ÷ 1.1, 아니면 판매가 |
| 원가율 | 공통 원가 ÷ 기본 판매가의 공급가액 |
| 채널 수수료 | 채널 판매가 × 수수료율 (고객이 낸 금액 전체에 붙음) |
| 채널 순이익 | 채널 판매가의 공급가액 − 수수료 − 공통 원가 − 그 채널 전용 부자재 |
| 순이익률 | 채널 순이익 ÷ 채널 판매가의 공급가액 |
| 적정 판매가 | 공통 원가 ÷ 목표 원가율 (× 1.1, 부가세 포함이면) → 100원 단위 올림 |

대시보드 원가율과 적정 판매가는 **공통 원가** 기준입니다. 채널 전용 부자재는 해당 채널의 순이익에서만 뺍니다.

### 계산 예시: 청포도 에이드 (판매가 4,500원, 부가세 포함, 목표 원가율 30%)

| 재료 | 단가 | 사용량 | 원가 |
|---|---|---|---|
| 얼음 | 1000g 2,800원 → 2.8원/g | 200g | 560원 |
| 탄산수 | 500ml 1,000원 → 2원/ml | 300ml | 600원 |
| 청포도 시럽 | 2000ml 15,000원 → 7.5원/ml | 60ml | 450원 |
| **합계** | | | **1,610원** |

- 공급가액: 4,500 ÷ 1.1 = 4,091원 (부가세 409원)
- 원가율: 1,610 ÷ 4,091 = **39.4%** → 경고 원가율 35% 이상이라 빨간색
- 매장(수수료 0%) 순이익: 4,091 − 0 − 1,610 = **2,481원** (60.6%)
- 배달앱(수수료 10%) 순이익: 4,091 − 450 − 1,610 = **2,031원** (49.6%)
- 적정 판매가: 1,610 ÷ 0.3 × 1.1 = 5,903 → **6,000원**

## 4. 데이터 구조 (Firestore)

모든 데이터는 로그인한 사용자 문서 아래에 있어 사용자끼리 완전히 분리됩니다. 보안 규칙(`firestore.rules`)은 본인 `uid` 아래만 읽고 쓸 수 있게 합니다.

```
users/{uid}
├─ ingredients/{ingredientId}
│    name: "우유"
│    unit: "ml"                 // g | ml | ea
│    purchaseAmount: 1000       // 구매량. 반제품이면 완성량
│    purchasePrice: 2800        // 구매가(원). 반제품이면 0
│    yieldRate: 1               // 수율 (0.9 = 90%)
│    recipe: [                  // 비어 있지 않으면 반제품
│      { ingredientId, amount, channelIds: [] }
│    ]
│    updatedAt
│
├─ menus/{menuId}
│    name: "카페라떼"
│    price: 4500                // 기본 판매가
│    channelPrices: { "배달앱": 5000 }   // 채널 id -> 판매가
│    recipe: [
│      { ingredientId, amount: 200, channelIds: [] },          // 모든 채널
│      { ingredientId, amount: 1,   channelIds: ["배달앱"] }   // 배달 전용 부자재
│    ]
│    updatedAt
│
└─ settings/default
     warningRate: 0.35
     targetRate: 0.30
     vatIncluded: true
     channels: [ { id: "매장", name: "매장", feeRate: 0 }, ... ]
```

- 새로 추가한 필드(`yieldRate`, `recipe`, `channelPrices`, `channelIds`, `vatIncluded`, 채널 `id`)는 없으면 기본값으로 읽으므로, 예전에 저장한 데이터도 그대로 동작합니다.
- 기존 채널은 이름을 id로 쓰고, 새로 추가한 채널은 생성 시각으로 id를 만듭니다.

## 5. 코드 구조

계층은 모델 → 계산 → 데이터 → 프로바이더 → 화면 순서로 한 방향으로만 의존합니다.

```
lib/
├─ main.dart                 Firebase 초기화, 익명 로그인(실패 시 다시 시도 화면)
├─ app.dart                  MaterialApp, 하단 탭
├─ core/format.dart          금액·퍼센트·수량 표시
├─ models/                   Ingredient, Menu·RecipeItem, AppSettings·SalesChannel, UnitType
├─ domain/cost_calculator.dart   모든 계산 (단가, 원가, 순이익, 적정가, 경고 판단)
├─ data/cost_repository.dart     Firestore 읽기·쓰기 (Firestore를 직접 다루는 유일한 곳)
├─ providers/providers.dart      Riverpod 프로바이더
└─ screens/                  화면 6개
test/
├─ cost_calculator_test.dart 계산 로직 테스트
└─ format_test.dart          표시 함수 테스트
```

- 데이터 흐름: Firestore → 리포지토리 → `StreamProvider`(재료·메뉴·설정) → `menuCostsProvider`(계산 결과) → 화면. 재료 하나의 값이 바뀌면 관련 화면이 모두 자동으로 다시 그려집니다.
- 저장·삭제는 서버 응답을 기다리지 않습니다. Firestore가 기기에 먼저 반영하고 나중에 동기화하므로, 오프라인에서도 화면이 멈추지 않습니다.

## 6. 개발 환경

### 처음 설정
Firebase 설정 파일(`lib/firebase_options.dart`, `android/app/google-services.json`, `firebase.json`)은 저장소에 포함하지 않습니다. 본인 Firebase 프로젝트를 연결해서 만듭니다. 자세한 순서는 `README.md`에 있습니다.

1. Firebase 콘솔에서 익명 로그인을 켜고 Firestore 데이터베이스를 만듭니다.
2. `flutterfire configure`로 앱을 연결합니다.
3. `firebase.json`에 `"firestore": {"rules": "firestore.rules"}`를 넣고 `firebase deploy --only firestore:rules`로 규칙을 배포합니다.

### 자주 쓰는 명령
| 명령 | 용도 |
|---|---|
| `flutter run` | 앱 실행 |
| `flutter test` | 테스트 (Firebase 없이 동작) |
| `flutter analyze` | 정적 분석 |
| `firebase deploy --only firestore:rules` | 보안 규칙 배포 |

### 자동 테스트
`main`에 푸시하거나 PR을 올리면 GitHub Actions(`.github/workflows/test.yml`)가 `flutter test`를 실행합니다. Firebase 설정 파일이 저장소에 없어서 `flutter analyze`는 CI에서 돌리지 않습니다.

## 7. 알려진 제한

- **익명 로그인**: 앱을 지우거나 기기를 바꾸면 데이터에 다시 접근할 수 없습니다. 실제 사용 전에 구글·카카오 로그인 연결(`linkWithCredential`)이 필요합니다.
- **첫 실행은 인터넷 필요**: 익명 로그인에 네트워크가 필요합니다. 한 번 로그인한 뒤에는 오프라인에서도 쓸 수 있습니다.
- **부가세**: 10%로 고정입니다. 식자재 매입세액공제나 면세 농산물 의제매입세액공제는 반영하지 않고, 구매가를 그대로 원가로 씁니다.
- **반제품은 한 단계만**: 반제품 안에 다른 반제품을 넣을 수 없습니다.
- **수량 정밀도**: 사용량·구매량은 소수 셋째 자리까지 다룹니다.
